# AI Mock Interview

> 一个会看你简历出题、会层层追问、会打分复盘的技术岗 AI 模拟面试官。

背完八股，一被追问就卡住？面试挂了却不知道原因？这个项目把真实面试中“出题 → 追问 → 评价”的过程交给 AI。你可以在真正面试之前，先被同一套问题问一遍，再拿到一份可以照着做的改进清单。

- **按简历出题**：上传 PDF、Word、图片，或直接粘贴文本。能抽出文字的 PDF / Word 在浏览器本地直接读取；扫描件和图片页在浏览器里做 OCR。大约一半题目来自你简历里的具体项目，另一半是和岗位、JD 相关的八股题和场景题。
- **层层追问**：回答模糊就追问具体数据，回答得好就继续往深挖，每题最多追问 3 层。
- **四维评分**：从准确性、深度、实战关联、表达四个维度给每题打 1–5 分，并指出遗漏的要点。
- **复盘报告**：给出总分、各维度得分、最需要补的 3 个弱项及补法，并可逐题回看问答和参考要点。
- **能力成长**：首页展示总分趋势、各维度相比之前的变化，以及反复出现的弱项，可按岗位筛选。
- **专项练习**：针对反复出现的弱项，一键出 3 道围绕该知识点的题，并跟踪练习后的得分。
- **Skill 题包**：用一个 Markdown 文件描述“某类面试怎么面”——出题指引、评分要点和精选题，按岗位和级别自动选用。内置 Java 后端校招、前端校招两个题包，欢迎贡献更多方向，见 [packs/README.md](packs/README.md)。
- **面经题库**：粘贴或上传真实面经，AI 整理成题目和参考要点，并标出与题库重复的题；开始面试时优先从题库里挑题，考得少的优先。
- **算法手撕**：遇到算法题，右侧打开代码编辑器，支持 Java、Python、C++、Go、JavaScript。可以填自定义输入试跑。题目如果带了预置测试用例（系统里的预置算法题，或题包里写了用例的题），点「判题」或「提交代码」时会逐个运行，并标出每一例通过还是失败；结果会和代码一起交给面试官追问。容器运行时和沙箱镜像都就绪时，代码在容器里跑；否则用本机已安装的语言环境，没装的语言只能写不能跑。详见下文「算法题运行」。
- **语音面试**：面试官的问题可以朗读出来，回答可以用说的，识别成文字后先改再发送。使用浏览器自带的语音功能，声音不经过本项目的服务端；语音输入在 Chrome 里需要能访问 Google，国内建议用 Edge，不支持时照常打字。
- **视频面试（可选）**：面试时可以打开摄像头，预览、录像，并在浏览器里回放。仪态建议看取景、光线、头和上半身是否明显出画，在浏览器本地分析。画面和录像只留在这次页面的内存里，不上传到本项目的服务端，也不发给模型服务商。没有摄像头、浏览器不支持或拒绝授权时，文字和语音面试照常进行。详见下文「视频面试」。
- **任意模型**：支持所有 OpenAI 兼容接口，包括 DeepSeek、通义千问、Kimi，也可以接你自建的模型网关。
- **轻量**：前端 React + Vite，后端是零依赖的 Node 服务，不需要数据库。

## 快速开始

需要 Node.js 20.19+。

```bash
git clone https://github.com/a-xiaoyuan/ai-mock-interview.git
cd ai-mock-interview
npm install
npm run dev
```

打开 http://localhost:5173 。`npm run dev` 会同时启动 Vite 开发服务器（5173）和后端 API 服务（3000），Vite 会把 `/api` 请求转发给后端。

部署或日常使用时，先构建再启动，只需要一个端口：

```bash
npm run build
npm start          # 打开 http://localhost:3000
```

不配置模型也能运行：此时为 **mock 模式**，题目是固定的，分数按回答长度粗略给出，适合先体验流程。

## 接入模型

把 `.env.example` 复制为 `.env`，然后填写：

```bash
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-xxxx
LLM_MODEL=deepseek-chat
```

| 变量 | 说明 | 默认值 |
| --- | --- | --- |
| `LLM_BASE_URL` | OpenAI 兼容接口地址 | `https://api.deepseek.com/v1` |
| `LLM_API_KEY` | API Key；不填则进入 mock 模式 | 空 |
| `LLM_MODEL` | 出题、评分、复盘用的模型，建议选推理强的 | `deepseek-chat` |
| `LLM_FAST_MODEL` | 面试官说话用的模型，建议选响应快的 | 同 `LLM_MODEL` |
| `LLM_JSON_MODE` | 模型支持 `response_format: json_object` 时设为 `1` | `0` |
| `PORT` | 服务端口 | `3000` |
| `CODE_RUNNER` | 谁可以调用算法题运行：`local` 只接受本机请求，`on` 允许任何来源，`off` 关闭 | `local` |
| `CODE_SANDBOX` | 在哪里跑：`auto` 能用容器就用，否则回退本机；`on` 必须用容器，否则报错；`off` 始终本机进程 | `auto` |
| `CODE_SANDBOX_IMAGE` | 沙箱镜像名 | `ai-mock-interview-sandbox:local` |

> 自定义输入和预置用例判题用同一套运行器。默认 `CODE_SANDBOX=auto`：容器就绪就在容器里跑，否则回退到本机进程（不是安全沙箱）。怎么启用、公网部署还要注意什么，见下文「算法题运行」。容器隔离不是绝对安全。

常用接口地址：

| 服务商 | `LLM_BASE_URL` | 示例模型 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |

API Key 只保存在服务端，不会发送到浏览器。

## 工作原理

面试官由 4 个分工明确的 Agent 组成，而不是一个大 Prompt。提问和打分由不同的 Agent 负责，避免面试官“自己出题、自己夸”。

```
简历 + JD ──▶ Planner 生成大纲
                  │
                  ▼
          Interviewer 提问 ◀──────────────┐
                  │                       │ 追问（每题 ≤ 3 层）
                  ▼                       │
             候选人回答 ──▶ Judge 评分 ────┤
                                          │ 下一题
                                          ▼
                              全部结束 ──▶ Reviewer 复盘报告
```

| Agent | 接口 | 职责 |
| --- | --- | --- |
| Planner | `POST /api/plan` | 根据简历、JD、岗位和级别生成题目，以及每题的参考要点 |
| Interviewer | `POST /api/ask` | 以流式输出面试官的下一句话：开场、追问或换题 |
| Judge | `POST /api/judge` | 根据整道题的问答链打分，并决定继续追问还是换题，以 JSON 输出 |
| Reviewer | `POST /api/report` | 汇总全场，写出总体评价、亮点和弱项建议 |
| Extractor | `POST /api/extract` | 把面经原文整理成题目和参考要点，再与已有题库对照判重 |

评分标准（每个维度 1–5 分）：

| 维度 | 看什么 |
| --- | --- |
| 准确性 | 事实和原理是否正确 |
| 深度 | 是否讲到底层机制、边界条件和取舍 |
| 实战关联 | 是否结合自己的项目，有没有具体数据 |
| 表达 | 是否先说结论再展开，条理是否清楚 |

所有 Prompt 都集中在 `server.js` 的 `PROMPTS` 对象里，方便修改和试验。

## 简历和扫描件

简历文件只在浏览器本地读取，不会上传到本项目的服务端。提取出的文字会随出题请求发送给你配置的模型服务商，请按需对个人信息做脱敏。

| | |
| --- | --- |
| 直接抽文字 | 有文字层的 PDF、有正文的 Word（.docx）、TXT、Markdown。这些文件不经过 OCR。 |
| 扫描件 PDF | 某一页去掉空白后不足约 20 个字，并且这一页含有图像，或者整份 PDF 都几乎没有文字时，把该页画出来再识别。同一份文件里，文字够用的页仍走原来的提取。 |
| 图片 | PNG、JPEG、WebP、BMP、GIF。手机照片会按 EXIF 方向转正；长边超过 2400 像素会先在本地缩小。扫描页会先画成图，长边大约 2200 像素。 |
| 语言 | 简体中文和英文一起识别（`chi_sim` + `eng`）。 |
| 页数和大小 | 最多 10 MB、前 10 页。旧版 `.doc` 不支持。 |

识别用的是浏览器里的 [Tesseract.js](https://github.com/naptha/tesseract.js)。引擎和语言包做成站点自己的静态文件（`/ocr`），第一次用到才下载，不打进首屏。简体中文语言包约 1.7 MB，英文约 3 MB，引擎按浏览器能力选一份，约 4 MB。网络正常时，第一次加载通常要十几秒到一分钟；同一浏览器之后会用缓存。每一页识别一般要几秒到二十多秒，页数多会更慢。界面会显示进度和已用时间。

能力边界：印刷体、正向、比较清晰的简体中文和英文效果较好。手写、严重模糊、复杂底纹、竖排、繁体中文，以及倒置、横放或明显倾斜的照片，可能认错，也可能认不出。手机照片会按 EXIF 方向转正。识别结果请对照原件改一改再开始面试。

## 视频面试

面试页右侧有一块「视频」，默认关闭。点「打开摄像头」之后才申请权限，并开始预览。可以录像、停止、回放，也可以清除。这是可选功能：没有摄像头、浏览器不支持、页面不是安全连接，或你拒绝授权时，文字作答和语音作答照常使用，开始面试和发送回答都不会被拦住。

| | |
| --- | --- |
| 预览 | 前置摄像头，画面在页面里镜像显示，方便看自己。只申请画面，不申请麦克风，避免占用语音输入。 |
| 录像和回放 | 录的是画面，不含声音。单段最长 3 分钟，只保留最新一段。数据是浏览器内存里的 Blob，用本地对象 URL 回放。刷新或离开面试页就没有了。 |
| 仪态建议 | 打开摄像头后才懒加载模型。大约每半秒看一帧，建议稳定出现才显示。录像停止后，再按这一段里反复出现的情况写几句。 |
| 模型 | [MediaPipe Pose Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker) lite（float16，Apache-2.0）。引擎和模型是站点自己的静态文件（`/posture`），不打进首屏。有 SIMD 的浏览器下载约 11 MB 的引擎，很老的浏览器会改用约 10 MB 的兼容引擎，模型约 5.5 MB。 |
| 建议看什么 | 有没有人、是不是偏出画面、头是否太靠上或太靠下、离镜头太近或太远、肩膀是否出画或明显一高一低、是不是侧脸、脸部偏暗、过亮、逆光或左右脸亮度差很大。多人入画时会提醒只留自己。 |

隐私：画面只在这台浏览器里预览和分析，录像只留在本次页面的内存里。本项目没有接收视频的接口，不会把画面或录像上传到服务端，也不会把它们发给你配置的模型服务商做仪态分析。下载的只是姿态模型本身。

能力边界和局限：

- 第一次打开摄像头要下载并初始化模型。网络正常时常见是十几秒，慢的时候更久；同一浏览器之后走缓存，初始化仍可能要几秒。模型没加载成功时，预览和录像仍然可用，只是暂时没有仪态建议。
- 低照度、逆光、边缘光（一侧亮一侧暗）可能把脸判暗，也可能直接认不出人。
- 侧脸、只露出一部分头或肩膀、手挡住脸、摄像头角度很斜时，容易误判。
- 多人入画，或背景里有明显的人像、海报，可能被当成第二个人。
- 建议只描述取景和光线，不评价表情、服装或回答内容。它是练习时的参考，不是面试官的评分。

## 算法题运行

自定义输入和预置用例判题走同一套运行器，支持 Java、Python、C++、Go、JavaScript。自定义运行时，编译和运行一共 10 秒；自动判题时，编译单独 10 秒，每个用例再各 10 秒。容器启动的时间也算在里面。输出过长会被截断。

谁可以调用，和代码在哪里跑，是两个开关：

| | |
| --- | --- |
| `CODE_RUNNER=local` | 默认。只接受来自本机（127.0.0.1）的请求。 |
| `CODE_RUNNER=on` | 任何来源都能调用。前面有 nginx 等反向代理时，服务看到的都是本机，`local` 挡不住外部访问。 |
| `CODE_RUNNER=off` | 关闭运行和判题。公网如果暂时不跑候选人代码，用这个。 |
| `CODE_SANDBOX=auto` | 默认。Docker 或 Podman 已启动，并且镜像已经构建好时，在容器里跑；否则回退到本机进程，启动日志会写明原因。本机没装容器时，练习路径和以前一样。 |
| `CODE_SANDBOX=on` | 必须用容器。运行时或镜像没就绪时直接报错，**不会**改回本机进程。 |
| `CODE_SANDBOX=off` | 始终用本机进程，代码和服务进程同一套权限。这不是安全沙箱。 |

本机练习什么都不用改。想启用容器时：

```bash
# 先安装并启动 Docker 或 Podman，再构建镜像（只使用 sandbox/ 作为构建上下文，不会把 .env 打进镜像）
npm run sandbox-image
# .env 里保持 CODE_SANDBOX=auto，或者显式写成 on
```

镜像里是 Debian 的 OpenJDK 17、Python 3、g++、Go 和 Node.js，只够跑标准库里的算法题，没有额外的第三方包。默认镜像名是 `ai-mock-interview-sandbox:local`，可以用 `CODE_SANDBOX_IMAGE` 换成自己的镜像。服务进程不是 root 时，容器用户和当前用户相同（Podman 会加 `--userns=keep-id`，让挂载目录的属主对得上）；服务以 root 运行时，容器使用镜像里的 uid 10001，不会以 root 跑候选人代码。

容器每次启动都会加上这些限制：

- 根文件系统只读，只把本次临时目录挂到容器里的 `/work`；`/tmp` 是内存盘
- 网络使用 `--network none`，没有出网网卡
- 去掉全部 capabilities，并加上 `no-new-privileges`
- 限制内存（768MiB）、CPU（1 核）和进程数（128），并关掉 core dump
- 不把宿主的环境变量传进容器，只放固定的语言运行需要的变量。`LLM_API_KEY` 以及其他密钥类变量不会进入容器，也不会传给本机回退时的子进程

公网如果要开放运行，请同时设置 `CODE_RUNNER=on` 和 `CODE_SANDBOX=on`，并确认镜像能建出来、服务启动日志里写的是容器沙箱。做不到就继续 `CODE_RUNNER=off`。不要用 `CODE_SANDBOX=auto` 或 `off` 对公网开放：`auto` 在容器没就绪时会回退到本机进程，`off` 一直如此。反向代理后面不要依赖 `CODE_RUNNER=local`。

这不是绝对安全。上面的限制能挡住常见的读密钥、访问外网和改系统文件，挡不住内核漏洞导致的容器逃逸，也挡不住在时限内占满一个 CPU，或把临时目录写得很大（跑完会删）。镜像里的系统包需要自己更新后重新构建。本实现不会把 Docker socket 挂进容器；请不要在别的地方把它挂给会接触候选人代码的进程。需要更强隔离时，可以再加 gVisor、Kata 一类的运行时，那要单独验证，本项目没有替你打开。

## 评分回归

改了 Judge 的 Prompt 或换了模型，评分可能悄悄变松或变严。`evals/judge-cases.json` 里有一组固定的问答，覆盖高质量回答、长篇空话、自信但错误、直接说不会、简略但正确、项目回答空泛等情况，每个用例写明各维度和总分的预期区间，以及该追问还是换题；另外列出几组“好答案必须高于差答案”的对比。

```bash
npm start                              # 先启动服务（读取 .env 里的模型配置）
npm run eval                           # 每个用例跑 3 次
npm run eval -- --runs 5 --only cache-strong,cache-verbose-empty
npm run eval -- --save-baseline        # 确认结果没问题后，保存为新的基线
npm run eval -- --pack java-backend-campus   # 带上题包的评分要点，检查它会不会把通用评分带偏
```

脚本会报告每个用例是通过、不稳定（多次结果不一致）还是失败，检查好坏对比是否成立，并和 `evals/baseline.json` 对比，标出平均总分变化 ≥ 2 或某个维度变化 ≥ 1 的用例。有用例失败或对比不成立时退出码为 1，可以放进 CI。

建议的流程：改 Prompt 前先跑一遍确认基线，改完再跑；有漂移时看是变好了还是变坏了，确认变好再 `--save-baseline`。提 Prompt 相关的 PR 时，请附上前后两次的运行结果。新增用例时，区间要宽到能容忍正常波动，又要窄到能抓住明显跑偏。

- AI 的评分和参考要点仅供练习参考，可能有错，不代表任何公司的真实标准。
- 上传的简历文件只在浏览器本地读取，扫描件和图片也是在浏览器里识别，不会把文件上传到本项目的服务端。提取出的文字会随出题请求发送给你配置的模型服务商，请按需对个人信息做脱敏。识别可能有错字，导入后请再看一眼。
