# Skill 题包

题包描述“某一类面试怎么面”：出题指引、评分要点和一组精选题。开始面试时，系统会按岗位和级别自动选用匹配的题包（也可以手动选），然后：

- **出题**：Planner 遵守题包的「面试官指引」，八股和场景题优先从题包的题目里挑。选中的题使用题包里人工校对过的参考要点。
- **评分**：Judge 在通用评分标准之外，参照题包的「评分要点」打分。

每个题包是一个 Markdown 文件，放在这个目录下，文件名与 `id` 一致。服务运行时修改题包会自动生效，不需要重启。

## 格式

````markdown
---
id: java-backend-campus          # 小写字母、数字和连字符，与文件名一致
name: Java 后端 · 校招            # 显示在首页的名字
description: 一句话说明适合谁、覆盖什么
version: 1                       # 内容有实质改动时加 1
author: 你的 GitHub 用户名
roles: [后端开发（Java）]          # 适用岗位，写法与首页的岗位选项一致
levels: [校招]                    # 适用级别；不写表示所有级别
---

## 面试官指引

出题时要遵守的规则：考察面、题目分布、怎么结合简历、什么情况下出算法题……（≤ 1500 字）

## 评分要点

这个方向特有的评分标准：哪些错误要重扣、什么样的回答才算有深度……（≤ 1500 字）

## 题目

### [八股] HashMap
HashMap 的底层结构是什么？put 一个元素的过程是怎样的？
- 参考要点 1
- 参考要点 2
````

- 题目标题格式为 `### [阶段] 知识点`，阶段只能是 `八股`、`场景题`、`项目深挖`、`算法` 之一。
- 标题下面的正文是题目，`-` 开头的列表是参考要点，至少 2 条，建议 3–5 条。
- 一个题包最多 40 道题。
- 算法题可以在参考要点后面加 `cases` 代码块，写预置测试用例。提交代码时会按这些用例自动判题（和自定义输入运行是同一套本机运行器，不是容器沙箱）。没有用例的算法题仍然只是口述题。只有「算法」阶段可以写用例，最多 8 个。输入和输出按文本比较：忽略每行行尾空格，以及整段开头、结尾的空行。
- 用例之间用单独一行的 `===` 隔开，每个用例里用单独一行的 `---` 把输入和输出隔开。第一行可以写 `name: 名称`。用例正文里不要出现单独一行的 ` ``` `。

````markdown
```cases
name: 样例
3
---
3
===
name: 一阶
1
---
1
```
````

## 贡献一个题包

1. 复制一个现有题包，改成你熟悉的方向，例如「Go 后端 · 社招」「算法岗 · 校招」「测试开发」。
2. 运行 `npm run check-packs` 检查格式。
3. 启动服务，选用你的题包面一场，看出题和评分是否符合预期。
4. 如果改了评分要点，运行 `npm run eval -- --pack 你的题包id`，确认通用评分用例没有被带偏。
5. 提 PR，在描述里写明题包的来源（自己的面试经历、公开面经整理等）。

参考要点要**准确**：评分时会拿它对照候选人的回答，错误的要点会让评分跟着出错。不确定的内容宁可不写。
